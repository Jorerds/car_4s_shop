## 1. 项目背景与目标

### 1.1 背景

4S店目前车型展示与试驾预约依赖线下到店和电话沟通，存在以下问题：

- 顾客无法提前在线了解车型与配置，到店决策成本高；
- 试驾预约靠人工登记，时段冲突、车辆分配混乱；
- 销售跟进过程无系统沉淀，客户线索易流失；
- 门店经营数据分散，管理者无法实时掌握预约、转化情况。

### 1.2 目标

1. 顾客可在线浏览车型、查看配置、对比车型、预约试驾，降低到店决策成本；
2. 试驾预约全流程线上化：顾客提交 → 时段库存自动管控 → 销售确认并分配试驾车辆 → 通知顾客 → 试驾记录归档；
3. 销售跟进过程系统化，客户线索可追踪、不流失；
4. 管理端提供统计报表与导出能力，支撑门店经营决策。

### 1.3 成功指标（上线后 3 个月）

| 指标             | 目标值        |
| -------------- | ---------- |
| 线上预约试驾占全部试驾的比例 | ≥ 60%      |
| 预约 → 到店试驾转化率   | ≥ 50%      |
| 试驾时段冲突投诉       | 0 起        |
| 销售跟进记录覆盖率      | 100%（每条线索） |

## 2. 用户角色与权限

| 角色      | 说明    | 核心权限                                |
| ------- | ----- | ----------------------------------- |
| 游客（未登录） | 浏览顾客  | 浏览车型、查看配置、车型对比、预约试驾（手机号验证码验证）       |
| 顾客（已登录） | 注册用户  | 游客全部权限 + 查看/取消自己的预约、接收系统内通知         |
| 销售顾问    | 门店销售  | 确认/拒绝预约、分配试驾车辆、登记试驾记录、跟进客户、查看个人业绩看板 |
| 店管理员    | 门店管理者 | 车型与配置维护、试驾车与时段管理、用户（账号）管理、全部统计报表与导出 |

**权限原则**：基于角色的访问控制（RBAC），不同角色登录后看到不同菜单与数据范围；销售顾问仅能查看分配给自己的客户与预约，管理员可见全量数据。

## 3. 功能需求

### 3.1 用户登录与权限（RBAC）

- 顾客端：手机号 + 短信验证码注册/登录（验证码即注册，简化流程）。
- 销售顾问、店管理员：账号 + 密码登录，账号由管理员在后台创建与停用。
- 登录后按角色渲染菜单与路由，后端接口逐一鉴权，不允许仅前端隐藏。
- 顾客可浏览、预约而不登录；登录后绑定手机号，自动关联该手机号名下的历史预约记录。

### 3.2 车型管理（店管理员）

- 维护车型基础信息：车型名称、品牌、车系、指导价、车身类型（轿车/SUV/MPV 等）、能源类型（燃油/纯电/混动/增程等）、图片集（主图 + 多图，支持排序）。
- 车型状态：在售 / 停售；停售车型不在 C 端展示，但历史预约与试驾记录保留可查。
- 车型信息修改留痕（修改人、修改时间）。

### 3.3 配置参数管理（店管理员）

- 按车型维护详细配置参数，分组管理：**动力 / 底盘 / 车身 / 安全 / 舒适 / 科技** 六类。
- 每组参数为键值对结构（参数名 + 参数值），支持增删改。
- 配置参数同时服务于 C 端详情页展示与车型对比功能。

### 3.4 车辆展示（C 端）

- 车型列表页：卡片式展示（主图、名称、指导价、能源类型、车身类型）。
- 多维度筛选与排序：品牌、价格区间、能源类型、车身类型；按价格/热度排序。
- 车型详情页：图片集轮播、指导价、基础信息、六组配置参数完整展示、预约试驾入口。

### 3.5 车型对比（C 端）

- 顾客可从列表或详情页将车型加入对比栏，**支持 2–3 款**车型同时对比。
- 对比页按六组配置参数逐项横向排列，差异项高亮显示。
- 对比页提供各车型的"预约试驾"快捷入口。

### 3.6 预约试驾（C 端）

- 预约信息：选择车型 → 选择试驾日期与时段 → 填写姓名、手机号（游客需短信验证码校验）、备注（选填）。
- **时段库存自动管控**：
  - 时段以"车型 + 日期 + 时间段"为粒度设置可约容量，由管理员维护（见 3.9）；
  - 顾客仅能看到并选择有余量的时段；
  - 预约提交成功即占用 1 个名额（含待确认状态），销售拒绝或顾客取消后名额自动释放；
  - 并发提交时以后端校验为准，防止超约。
- 同一手机号对同一车型同一天仅允许存在 1 条有效预约（待确认/已确认），防止重复提交。
- 登录用户可在"我的预约"中查看预约状态、取消未完成的预约；**试驾开始前 2 小时内不可取消**（此前可自助取消，名额自动释放）。

### 3.7 试驾确认（销售顾问）

- 销售顾问查看待确认预约列表（按提交时间排序），可执行：
  - **确认**：从该车型的可用试驾车中分配一辆（同一时段一辆车只能分配给一个预约），确认后预约生效；
  - **拒绝**：填写拒绝原因，名额自动释放。
- 确认/拒绝后自动通知顾客，**双通道**：
  - 系统内消息（顾客登录后可见）；
  - 短信通知（对接第三方短信服务商）。
- 游客预约的，短信为唯一可达通道；系统内消息在其后续用手机号登录后可见。

### 3.8 试驾记录（销售顾问）

- 试驾完成后，销售顾问登记试驾记录：关联预约、实际试驾车型与车辆、试驾时间、顾客反馈（评分 1–5 + 文字评价）。
- 顾客未到店可标记"爽约"，并计入统计。
- 试驾记录与预约、客户档案关联，全程可追溯。

### 3.9 试驾车与时段管理（店管理员）

- 维护试驾车列表：车牌号、所属车型、状态（可用/停用）。
- 维护试驾时段计划：**时段粒度为 1 小时**，按车型（或具体试驾车）设置每日可约时段及容量，支持批量生成（如按周复制）。
- 停用中的试驾车不参与分配，其已占用的未来时段名额自动释放并通知受影响顾客（短信）。

### 3.10 客户跟进（销售顾问）

- 顾客提交预约后自动生成客户线索档案（以手机号为唯一标识合并）。
- 销售顾问对客户记录跟进情况，跟进类型：**电话 / 到店 / 试驾 / 成交**。
- 跟进记录包含：跟进时间、类型、内容备注、下次跟进计划时间。
- 客户详情页聚合展示：基本信息、预约记录、试驾记录、跟进时间线。
- 线索分配：新线索默认进入公共池或按规则分配给销售（一期简化为管理员手动分配/销售自行认领）。

### 3.11 统计报表与导出（店管理员）

四类报表，均支持表格 + 图表（趋势图/柱状图/漏斗图）展示，支持导出 **Excel / CSV**，支持按日期范围筛选：

| 报表      | 核心指标                              |
| ------- | --------------------------------- |
| 预约/转化报表 | 预约量趋势、预约 → 确认 → 到店试驾 → 成交转化漏斗、爽约率 |
| 销售业绩报表  | 各销售顾问的跟进量、预约确认率、试驾完成量、成交量及排行      |
| 客户报表    | 新增客户数趋势、客户状态分布（新线索/跟进中/已试驾/已成交）   |
| 车型热度报表  | 车型浏览量、被对比次数、预约量排行                 |

## 4. 核心业务流程

### 4.1 预约试驾主流程

```
顾客浏览车型 → (对比车型) → 选择车型/日期/时段（库存校验）
→ 填写姓名+手机号（游客：短信验证码）→ 提交预约（占用名额，状态：待确认）
→ 销售顾问确认并分配试驾车（状态：已确认）→ 短信+站内消息通知顾客
→ 顾客到店试驾 → 销售登记试驾记录与顾客反馈（状态：已完成）
→ 销售继续跟进（电话/到店/试驾/成交）→ 成交归档
```

分支：销售拒绝 → 名额释放 + 通知顾客；顾客取消 → 名额释放；顾客爽约 → 记录爽约。

### 4.2 预约状态机

| 状态  | 含义           | 可流转至            |
| --- | ------------ | --------------- |
| 待确认 | 顾客已提交，等待销售处理 | 已确认 / 已拒绝 / 已取消 |
| 已确认 | 销售已确认并分配试驾车  | 已完成 / 已取消 / 已爽约 |
| 已拒绝 | 销售拒绝（附原因）    | 终态              |
| 已取消 | 顾客主动取消       | 终态              |
| 已完成 | 试驾完成，已登记试驾记录 | 终态              |
| 已爽约 | 顾客未按约到店      | 终态              |

## 5. 非功能需求

| 类别   | 要求                                                         |
| ---- | ---------------------------------------------------------- |
| 性能   | 页面首屏加载 ≤ 3s；列表/详情接口响应 ≤ 500ms；支持单店日常并发（峰值按 100 在线用户设计）     |
| 安全   | 接口鉴权（RBAC）；短信验证码防刷（同号码 1 分钟 1 条、单日内上限）；密码加密存储；防 SQL 注入/XSS |
| 可用性  | 单门店内部系统，可用性目标 99.5%；数据每日备份                                 |
| 兼容性  | 顾客端适配 PC 与手机浏览器（响应式 H5）；管理端以 PC 浏览器为主                      |
| 可观测性 | 关键操作（预约、确认、分配、导出）记录结构化日志，带请求 ID                            |
| 数据合规 | 顾客手机号等个人信息加密存储/脱敏展示，导出操作记录审计日志                             |

## 6. 一期范围边界（明确不做）

- 二手车业务、整车在线下单/支付定金；
- 售后保养维修预约；
- 微信小程序 / 原生 App（预留移动端 H5 即可）；
- 在线客服 / IM 即时沟通；
- 多门店/集团化管理（单门店设计，数据模型预留门店字段）；
- 线索自动分配规则引擎（一期手动分配）。

## 7. 依赖与风险

| 事项        | 说明                                | 应对                                                   |
| --------- | --------------------------------- | ---------------------------------------------------- |
| 短信服务商     | 验证码与通知短信依赖第三方（阿里云/腾讯云），需企业资质与签名审核 | 开发期通过短信接口抽象 + 模拟实现（打日志）解耦，业务代码不受影响；服务商后定，配置切换；尽早申请资质 |
| 车型基础数据初始化 | 首批车型、配置参数、图片需人工录入                 | 提供后台录入界面；支持批量导入（二期）                                  |
| 时段容量规划    | 容量设置过低影响转化，过高导致销售/车辆资源不足          | 上线初期保守设置，按爽约率与确认数据迭代调整                               |
| 游客线索质量    | 游客可预约带来无效线索风险                     | 手机号验证码 + 同号重复预约限制 + 爽约统计                             |
