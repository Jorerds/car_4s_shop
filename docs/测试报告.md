## 2026-10-01 · 缺陷修复：登录空表单提示不友好

| 项目   | 内容                                                          |
| ---- | ----------------------------------------------------------- |
| 现象   | 登录表单留空提交，提示 `body.username: String should have at least 1 character`（Pydantic 英文原文） |
| 复现   | 新增 3 个接口测试用例：空账号 / 空密码 / 空请求体 → 断言返回 422 且含中文"XX不能为空"         |
| 修复   | ① 后端 `AccountLoginRequest` 用 `BeforeValidator` + `PydanticCustomError` 输出中文提示（`validate_default=True` 覆盖字段缺失场景）；② 异常处理器去掉 `body.` 前缀；③ 前端登录表单加必填规则，空表单本地拦截不发起请求 |

### 根因

Pydantic v2 默认校验错误为英文技术文案，且原异常处理器把 `loc`（含 FastAPI 注入的 `body.` 前缀）与英文 msg 直接拼接透传给前端；前端表单未做提交前必填校验，导致用户直接看到底层错误。

### 开发过程中发现的问题与处理

1. **测试夹具未显式 flush 导致关系读不到**：`autoflush=False` 下 fixture 中 `add()` 的配置/图片对象未 flush，请求处理查询不可见。
   - 处理：夹具 `_add_config`/`_add_image` 显式 `flush()`。
2. **SQLAlchemy 身份映射过期读（配置替换后同会话读到旧值）**：`query().delete()` 绕过会话状态，删除-重插后同会话 selectinload 返回过期对象（SQLite 主键复用加剧）。
   - 处理：仓储层删除/更新改走 ORM 对象，变更后 `expire_all()` 使缓存过期。
3. **`expire_all()` 顺序错误丢弃未落库修改**：先过期后 flush 会丢弃内存改动。
   - 处理：`clear_main_images` 调整为"先 flush 再过期"。
4. **`UPLOAD_DIR` 相对路径依赖执行目录**：从 `backend/` 启动服务时挂载不到种子写入的图片。
   - 处理：默认路径锚定项目根（`PROJECT_ROOT/data/uploads`）。
5. **uvicorn `--reload` 在本环境偶发不生效**（路由/静态挂载变更后仍 404）：全量重启进程后恢复。
   - 经验：验证服务行为以全量重启后为准；疑似与 Windows 下 watchfiles 子进程替换有关。

### 开发过程中发现的问题与处理

1. **导出解包顺序错误**：`export()` 将 `_export_rows` 的 `(headers, rows)` 接反，Excel 写入时报类型错误。处理：修正解包顺序。
2. **路径参数误用 `Query` 约束**：FastAPI 断言失败。处理：改用 `Path(pattern=...)`。
3. **测试撞时段唯一约束**：报表辅助函数同车型同天同时段造多条预约。处理：辅助函数加时段参数。
4. **Vite 代理缺 `/exports`**：导出文件 URL 被 SPA 回退截获。处理：补代理。

### 偏离记录

导出为**同步生成**（原技术方案为 Celery 异步 + 站内通知下载链接）：单店量级秒级完成、开发期无常驻 Worker；数据量增大时可平滑迁移。已同步修正技术方案偏差说明。
